# Governance

OpenKartLine begins as a maintainer-led community project.

## Decision making

- Routine changes are decided through issue and pull-request review.
- Physics claims require reproducible tests or cited references.
- Changes to public formats, core architecture, licensing, or safety behavior require an ADR and an open review period.
- Maintainers seek consensus; when consensus is not possible, the repository owner makes the decision and records the rationale.

## Roles

- **Contributor:** submits issues, tests, documentation, data, or code.
- **Reviewer:** regularly reviews a defined area and demonstrates relevant knowledge.
- **Maintainer:** can merge changes, manage releases, and uphold project policies.

Roles are earned through sustained, constructive participation. Maintainers must disclose material conflicts of interest.

## Compatibility

Versioned project files follow semantic compatibility rules documented in [DATA_FORMATS.md](docs/DATA_FORMATS.md). Stable releases will use semantic versioning.
